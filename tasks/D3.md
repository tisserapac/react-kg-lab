# D3: extract a `useMovieFilter` custom hook (refactoring)

**The task** (full spec in `../movie-watchlist/tasks/D3.yaml`): move the filter state and
the calculation of the visible movies out of `WatchlistPage` into a new hook,
`useMovieFilter(movies)` in `src/hooks/useMovieFilter.js`, returning
`{ filter, setFilter, visibleMovies }`. The page must behave exactly as before.

## What information matters

A refactoring changes structure but must not change behaviour. So the questions are
"what moves?" and "what could break?":

| Question | Why it matters | Query in `queries/D3.cypher` |
| --- | --- | --- |
| Which state does the page declare? | `filter` / `setFilter`, starting at `'all'`, moves into the hook. | `D3-1-state-to-move` |
| Which children receive the filter, as which props? | `FilterBar` gets `filter` and `onFilterChange`, `MovieList` gets `movies`. They must get the same values afterwards. | `D3-2-where-the-filter-flows` |
| Which handlers touch the filter? | `handleReset` sets it back to `'all'`; it must use the hook's setter. | `D3-3-handlers-on-the-page` |
| How do the existing hooks look? | Location (`src/hooks/`), default export, which React hooks they use: the new file should match. | `D3-4-hook-conventions` |
| Who renders the page? | The blast radius. `App` does, through a route; the page takes no props, so `App` needs no change. | `D3-5-callers` |
| Which files must the model read? | The page, and one existing hook as a style example. | `D3-6-files-to-read` |

For a refactoring, the **blast radius** (D3-2 and D3-5) matters most: everything that
depends on what is being moved.

## What the graph does not tell you

- **The calculated value.** `visibleMovies` is not state, so it is not a node. The graph
  shows that `MovieList` receives a prop called `movies`, not that its value is the
  filtered list. The model only learns that from the source.
- **The new hook.** It does not exist yet, so no query can find it. (The research
  pipeline's classifier even named `useMovieFilter` as an anchor; it matched nothing.)
- **Tests.** The tests are not in the graph, so it cannot say which tests check the
  filter.
