# D2: add a "Clear watched" button (feature addition)

**The task** (full spec in `../movie-watchlist/tasks/D2.yaml`): add a `clearWatched`
action to `MoviesProvider` that removes every watched movie, make it available through
the `useMovies` hook, and add a "Clear watched" button to the footer of `WatchlistPage`,
disabled when no movie is watched.

## What information matters

A new feature has to fit into what already exists. Before writing code, a developer (or
an LLM) needs to know:

| Question | Why it matters | Query in `queries/D2.cypher` |
| --- | --- | --- |
| Which page is at `/`, and in which file? | That is where the button goes. | `D2-1-page-at-route` |
| What is already on that page? | The button joins the footer; `handleReset` is an existing button to copy. | `D2-2-page-structure` |
| How does the page get the movie list? | Through `useMovies` → `MoviesContext` ← `MoviesProvider`. The new action travels the same way. Without the graph, nothing in `WatchlistPage.jsx` mentions `MoviesProvider`. | `D2-3-data-path` |
| Which actions are shared already, and where does the state live? | `clearWatched` should look like `deleteMovie` and use the same `setMovies`. | `D2-4-existing-actions` |
| Who else uses the hook? | `StatsPage` will see the new action too and must keep working. | `D2-5-other-consumers` |
| Which files must the model read? | The page, the Provider, and the hook in between. | `D2-6-files-to-read` |

The interesting part is **D2-3**: the two files the change touches are connected only
indirectly, through a hook and a Context. Following that path is exactly what a graph
is good at, and what text search over the files does badly.

## What the graph does not tell you

- **Behaviour.** The graph knows `deleteMovie` is shared, not what it does. The model
  still needs the source of `MoviesProvider.jsx` to write `clearWatched`.
- **Where in the JSX.** "The footer" is a `<div className="watchlist__footer">`; the graph
  has no node for it.
- **The rule "disabled when no movie is watched".** `watchedCount` comes from
  `useMovies`, but the graph does not record what a hook returns.
